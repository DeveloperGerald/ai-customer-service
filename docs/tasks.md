# 实施任务与验收清单

依据：[PRD](../PRD.md) · [架构](architecture.md) · [规则](../AGENTS.md)

当前仅完成需求评审文档。以下实现任务均未完成，不能把目录或空文件视为模块交付。每次只实施一个模块，不自动 git commit。

## 1. 执行约定

每个模块按顺序交付：接口/schema → 测试用例 → 实现 → pytest、ruff → 验收记录。仅修改所属模块及必要的该模块测试、迁移和接口文档；发现跨模块依赖先拆出前置任务，不顺手实现其他模块。

Trace、安全用例、业务失败用例随模块积累。文档阶段只做文档校验；实现阶段必须运行 pytest、ruff，不以没有测试为通过。

## 2. 顺序与依赖

| ID | 模块 / 依赖 | 交付物 | 验收重点 |
| --- | --- | --- | --- |
| T0 | 需求定稿 / 无 | 确认 D1–D4；冻结规则、首版 API 与状态边界 | 图片、人工、确认无矛盾；范围标识清楚 |
| T1 | 工程基础 / T0 的固定栈 | Python 3.14 依赖锁定、Pydantic 配置、FastAPI 生命周期、统一异常、structlog、pytest/ruff 配置、基础 Compose | 兼容性验证通过；服务可启动；缺少必需配置有明确错误；不硬编码密钥 |
| T2 | 身份及租户 / T1 | 演示身份签发与验证 schema、权限上下文、租户/账号迁移及种子 | 缺失或伪造租户拒绝；令牌过期拒绝；角色边界正确 |
| T3 | 订单物流 / T2 | 订单物流 schema、repository、迁移、幂等种子导入、只读应用服务 | 查无记录、多订单澄清数据、同租户他人订单、跨租户访问均覆盖 |
| T4 | 会话与状态 / T2 | 会话/消息/请求 schema、AgentState、checkpointer、请求去重、执行占用和恢复 | 重启可恢复；同会话并发返回明确结果；重复请求不重复消息；旧运行不能覆盖新状态 |
| T5 | 知识导入 / T2 | 文档分块 schema、迁移、受控导入、模型/维度配置、版本及摘要去重 | 重复导入可控；分块租户一致；版本和引用能定位；向量维度不混用 |
| T6 | RAG / T5 | 检索及证据 schema、租户过滤、引用校验、无依据处理 | 同问句三租户各自命中；注入指令不越权；无依据不伪造引用 |
| T7 | 工具框架 / T2、T3 | 工具协议、allowlist、参数与授权验证、审计迁移、超时及错误分类 | 成功、失败、拒绝均有审计；模型不能指定授权身份；未知写结果不盲重试 |
| T8 | 退款 / T3、T4、T6、T7 | 资格规则、pending_actions、确认/取消、事务幂等、模拟申请及查询 | 未确认不写入；过期/改参失效；重复及并发确认一单；新键不能绕过额度；直接 API 不绕过权限 |
| T9 | 人工交接 / T4、T7、D2–D4 | 交接 schema、迁移、幂等记录、上下文和队列查询 | 图片/明确人工按规则处理；摘要失败仍可交接；重复不入多次队；接管状态阻止自动写入 |
| T10 | Agent 编排 / T4、T6、T8、T9 | 意图 schema、节点、条件边、澄清、暂停恢复、统一生成 | 五条链路通过；多步骤退款正确；状态不串；异常有出口；达到步数上限终止 |
| T11 | HTTP / SSE / T10 | 聊天输入与事件 schema、流式接口、请求查询、心跳和错误契约 | 事件顺序及终态正确；流前后错误可区分；断线不重复业务；工具输出脱敏 |
| T12 | 前端 / T11、D2、D4 | 演示身份入口、聊天、引用、确认卡片、工具/交接状态、历史及请求恢复 | UTF-8/分块解析正确；重复点击安全；取消/失效可理解；无虚假图片上传或真人接入文案 |
| T13 | 观测完善 / T10、T11 | 汇总已有埋点、成本/延迟统计、脱敏检查 | 请求可关联完整链路；明确用户等待不计推理延迟；LangSmith 故障不改业务结果 |
| T14 | 冻结评测 / T10、T13 | 320 条目标数据集、自建评测脚本、固定评分规范、基线与失败报告 | 调优/验收分开；逐租户及场景报告；随机性、版本、样本量、成本清晰；无虚构指标 |
| T15 | 演示交付 / T12、T14 | Compose 集成、README、可重复数据导入、5/15 分钟讲解和失败恢复演示 | 新环境按文档启动；五条链路及重启恢复可复现；说明模拟边界 |

T1 的固定栈兼容性研究可在 D1–D4 确认前进行；依赖范围选择的实现不提前启动。T13/T14 的基础数据随模块积累，表中任务是最终完善与验收，不表示把埋点和测试延后。

## 3. 关键验收用例

| 编号 | 输入或故障 | 预期 |
| --- | --- | --- |
| A1 | tenant_a 身份指定 tenant_b | 拒绝，检索和工具均不执行越权访问 |
| A2 | 同租户消费者请求他人订单/会话 | 拒绝或统一不可见响应，不泄露是否存在 |
| A3 | 相同政策问题切换合法租户身份 | 引用分别来自各自租户及有效版本 |
| A4 | 知识片段要求忽略规则或调用退款 | 不获得权限，不执行未确认写入 |
| A5 | 退款缺少订单号 | 追问，取得订单后再校验，不猜订单 |
| A6 | 未确认、取消、过期 action 调用退款 API | 无业务写入，记录可解释结果及审计 |
| A7 | 同 action 并发确认、客户端重复点击 | 只产生一个申请，重复调用返回原结果 |
| A8 | 相同幂等键改变金额 | 冲突；更改操作需新确认且重新校验额度 |
| A9 | 提交成功后 SSE 断开 | 请求查询返回已提交结果，不重新退款 |
| A10 | checkpoint 前后进程退出 | 恢复时核对业务结果，不能重复执行 |
| A11 | 待确认后订单状态/政策实质变化 | 旧确认失效，重新展示或转人工 |
| A12 | 用户要求人工、描述裂珠或发送图片输入 | 按最终 D3/D4 交接，不识图、不判断实物质量 |
| A13 | 转人工摘要生成失败 | 保留原始上下文，交接仍可完成 |
| A14 | waiting_human 中再次要求退款 | 不自动业务写入，明确当前交接状态 |
| A15 | Redis 或 LangSmith 不可用 | 不丢失已持久化确认/业务结果，不产生重复写入；按依赖降级策略响应 |
| A16 | 检索无依据或政策冲突 | 不编造结论，不把信息不足解释为不符合退款条件 |
